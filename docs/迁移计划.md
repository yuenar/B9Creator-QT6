# B9Creator（Qt5）迁移到 Qt6 + RHI（QRhiWidget）渲染方案与计划

## 1. 目标与边界

### 1.1 总目标
将当前基于 Qt5 + 传统 OpenGL Widget（`QGLWidget`/`QtOpenGL`）的渲染与相关离屏绘制能力，迁移到 **Qt6 的 RHI 架构**，以 **`QRhiWidget` 替代原 `QGLWidget`/`QOpenGLWidget` 渲染**，并尽可能保持原项目的完整功能与交互行为。

### 1.2 必须保持的核心功能（按现代码推断）
- 3D 视图（`WorldView`）
  - 模型实例显示（含翻转/缩放/旋转/平移）
  - 视角控制（Top/Front/Right/...）、透视/正交切换
  - 支撑结构显示（上段/中段/下段、透明度随视角变化、隐藏/显示）
  - X-Ray 模式（基于 `xRayPercentage` 的裁剪/近裁剪调整逻辑）
  - Plasma Fence（越界提示）
  - 交互工具：选择、移动、旋转、缩放、支撑添加/删除/修改
  - picking（通过“颜色编码”选择实例/三角形/支撑部件）
- 2D/离屏切片渲染（`SliceContext` + `Slice/Loop` 的 `glBegin` 绘制）
  - 用于生成/预览/导出切片位图的渲染能力
- 大模型显示的降级策略（现使用 OpenGL Display List + `GL_OUT_OF_MEMORY` 时稀疏绘制）

### 1.3 非目标（建议不在首阶段实现）
- 对 UI/业务流程做大重构（仅为适配 Qt6/渲染后端而做必要改动）
- 立即提升画质/引入 PBR 等现代渲染特性（后续增量可做）

## 2. 现状分析（代码级别）

### 2.1 构建系统与模块依赖
- 工程为 qmake：`B9Creator.pro`
- Qt 模块：`core gui widgets svg opengl network concurrent`
- 平台链接：Windows 直接链接 `opengl32/glut32/glu32`（`gluPerspective/gluOrtho2D` 等依赖 GLU）

### 2.2 构建系统迁移（qmake → CMake，Qt6）

#### 2.2.1 目标
将项目从 `B9Creator.pro` 迁移到 **CMake（Qt6 官方推荐构建方式）**，并确保：
- Qt6 Widgets 应用可在 Windows/macOS/Linux 正常构建
- 后续引入 `QRhiWidget` 与 RHI 着色器（`.qsb`）时，**着色器在 CMake 构建期自动编译并被打包进资源**

#### 2.2.2 CMake 目录与文件组织建议
建议新增（或逐步演进到）以下结构：
- `CMakeLists.txt`（顶层）
- `src/`（必选：逐步把散落在根目录的源文件迁入，最终所有源码从该目录构建）
- `resources/`（qrc、图标等）
- `shaders/`（RHI shader 源文件：`.vert/.frag/.comp` 等）

建议以 `src/` 为最终归宿，但不强制“一次性搬完”。为了降低风险，可以先按以下方式落地：
- 先建立 `src/`，把 **入口与最少依赖的 UI 代码**（如 `main.cpp`、`mainwindow.*`、`b9nativeapp.*`）先迁入。
- 其余目录（`b9layout/`、`b9edit/`、`b9slice/` 等）可先保留原位置，通过 `src/CMakeLists.txt` 以相对路径引用；等 Qt6.9 + RHI 主链路稳定后再逐步搬迁进 `src/`。
- 最终目标：顶层只保留构建/资源/文档相关文件，业务源码统一在 `src/` 下。

推荐的 CMake 拆分方式：
- 顶层 `CMakeLists.txt`：只负责 `project()`、Qt 依赖、全局编译选项、以及 `add_subdirectory(src)`。
- `src/CMakeLists.txt`：定义 `qt_add_executable()` 目标、收集源文件、并注册 resources/shaders。

#### 2.2.3 Qt6 CMake 基础骨架（示例）
目标 Qt 版本：**Qt 6.9**。

关键点：
- `Qt6::Widgets`：主 UI
- `Qt6::Gui`：RHI/`QRhiWidget` 所在模块
- `Qt6::ShaderTools`：用于将 shader 源编译成 `.qsb`

示例（仅用于说明关键模块与调用方式，落地时需按实际文件列表补齐）：

```cmake
cmake_minimum_required(VERSION 3.21)
project(B9Creator VERSION 0.0.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(Qt6 6.9 REQUIRED COMPONENTS
  Core Gui Widgets Svg Network Concurrent ShaderTools)

qt_standard_project_setup()

qt_add_executable(B9Creator
  main.cpp
  mainwindow.cpp
  b9nativeapp.cpp
  # ...（按 B9Creator.pro 的 SOURCES/HEADERS/FORMS 逐步迁入）
)

target_link_libraries(B9Creator PRIVATE
  Qt6::Core Qt6::Gui Qt6::Widgets Qt6::Svg Qt6::Network Qt6::Concurrent
)

qt_add_resources(B9Creator "b9creator"
  PREFIX "/"
  FILES
    splash.png
)
```

#### 2.2.4 从 .pro 到 CMake 的迁移顺序（建议）
- **第 1 步**：先让 CMake 工程在 Qt6 下能编译并启动（哪怕渲染仍是旧 OpenGL/或临时 stub）。
- **第 2 步**：逐步加入 `FORMS`（`qt_add_ui`/`qt_wrap_ui` 或直接让 `qt_add_executable` 自动处理 `.ui`，取决于 Qt 版本与 CMake API）。
- **第 3 步**：加入 `qrc`（`qt_add_resources`）。
- **第 4 步**：处理第三方库（如 `qextserialport`）
  - 优先：把第三方库也改成 CMake 子目录 `add_subdirectory(...)`
  - 过渡：继续使用其 `.pri` 的代码需要转写为 `target_sources/target_include_directories`
- **第 5 步**：最后移除平台特定的 OpenGL/GLU/GLUT 链接项（等 RHI 完成后）

#### 2.2.5 Windows / macOS / Linux 平台差异
Qt6 + RHI 的目标是跨后端，因此：
- **Windows**：不再显式链接 `opengl32/glu32/glut32`（最终阶段移除）
- **macOS**：避免依赖系统 OpenGL（已弃用），RHI 将走 Metal
- **Linux**：RHI 可能走 Vulkan/OpenGL（取决于 Qt 构建与运行环境）

### 2.3 渲染相关关键文件与技术债
- **3D 主视图**：`b9layout/worldview.h/.cpp`
  - `class WorldView : public QGLWidget`
  - 固定管线：`glMatrixMode/glLoadIdentity/glTranslatef/glRotatef`
  - GLU：`gluPerspective`
  - 立即模式：`glBegin/glEnd`（部分绘制）
  - 状态机式渲染：`glEnable(GL_LIGHTING/GL_LIGHT0/...)`
  - 刷新机制：`QTimer` 16.66ms 调用 `UpdateTick()`，末尾 `glDraw()`
- **离屏/2D 切片**：`b9layout/slicecontext.h/.cpp`
  - `class SliceContext : public QGLWidget`
  - `setAutoBufferSwap(false)`（暗示用于离屏或抓取）
  - `gluOrtho2D` 建立 2D 投影
  - `Slice::Render()`、`Loop::RenderTriangles()` 使用 `glBegin(GL_TRIANGLES)` 等
- **几何显示列表（Display List）**：
  - `b9layout/modeldata.cpp`：`ModelData::FormNormalDisplayLists()` / `FormFlippedDisplayLists()`
  - `b9layout/b9modelinstance.cpp`：`RenderGL()` / `RenderPickGL()` / `FormTriPickDispLists()`
  - `b9supportstructure.cpp`：`B9SupportAttachmentData::FormDisplayList()`
  - 这些都属于 **OpenGL 旧时代特性**，在 RHI 下必须替换为：
    - 静态/动态 `VertexBuffer/IndexBuffer`
    - `GraphicsPipeline` + shader
    - 或者在过渡期使用 Qt6 `QOpenGLWidget`（但你明确要求最终以 `QRhiWidget` 为主）

### 2.4 迁移难点清单（决定分阶段策略）
- **固定管线/矩阵栈** → RHI 需要显式 shader + Uniform Buffer
- **Display List** → RHI 需要 GPU buffer + pipeline
- **GLU**（`gluPerspective/gluOrtho2D`）→ 改为 `QMatrix4x4::perspective/ortho`
- **picking 依赖 glColor 编码** → RHI 仍可保留“离屏渲染 + 读回像素”的思路，但实现方式要换为 `QRhiTextureRenderTarget` + `readback`
- **离屏 slice 渲染**：当前是 `QGLWidget` 执行 OpenGL 2D 绘制；RHI 需要单独的 offscreen pass（纹理渲染目标）

## 3. Qt6 + RHI（QRhiWidget）总体方案

### 3.1 总体策略：先“抽象渲染”，再“替换渲染后端”
为了最大限度保留功能并控制风险，推荐引入 **渲染抽象层**：
- **上层（业务/交互）**：尽量不动
- **中间层（渲染场景/命令）**：描述“画什么”
- **底层（渲染后端实现）**：OpenGL（旧）/RHI（新）二选一

在项目中，最合适的切入点是把 `WorldView` 的 `DrawInstances/DrawBuildArea/DrawMisc/DrawVisualSlice/...` 里的“OpenGL 指令”逐步抽取为“渲染数据 + draw call”，最终由 RHI 版本执行。

### 3.2 Qt6 渲染容器选择
- **最终容器：`QRhiWidget`**
  - 优点：Qt 官方推荐的 Widgets 场景下 RHI 渲染入口；跨后端（D3D11/12、Vulkan、Metal、OpenGL）
  - 注意：本计划锁定 **Qt 6.9**，以降低 `QRhiWidget`/RHI API 的版本差异风险

### 3.3 RHI 后端选择与策略
- Windows：优先 `D3D11`（成熟稳定，调试工具丰富）
- Linux：优先 `Vulkan` 或 `OpenGL`（按环境）
- macOS：`Metal`

建议策略：
- 默认后端跟随 Qt 自动选择
- 提供环境变量/配置项强制后端（便于排查驱动问题）

## 4. 关键模块迁移设计

### 4.1 WorldView（3D 视图）迁移到 `WorldViewRhiWidget`

#### 4.1.1 类替换
- 现：`WorldView : QGLWidget`
- 目标：`WorldViewRhiWidget : QRhiWidget`

保持对外接口尽量不变（便于 `B9Layout` 中替换）：
- 保留 `SetTool/GetTool/CenterView/TopView/...` 等 slot
- 保留鼠标/键盘事件处理接口
- 保留 `UpdateTick` 驱动（后续可改为基于 `QElapsedTimer` + requestUpdate）

#### 4.1.2 渲染生命周期映射（从 GL 回调到 RHI 回调）
`QRhiWidget` 的典型实现逻辑：
- 初始化 RHI 资源（pipeline、buffers、textures、samplers、UBO）
- 每帧：
  - 更新相机矩阵/对象变换 UBO
  - 开始 render pass
  - 画 build area / instances / supports / overlays
  - 结束 render pass

需要在计划里明确：
- 资源创建与销毁：窗口 resize、rhi 失效重建时必须重建相关资源
- 纹理/缓冲生命周期：与模型数据、支撑几何烘焙（bake）同步

#### 4.1.3 矩阵与相机（替换 `glMatrixMode`）
- 将 `ResetCamera()` 内的投影/视图变换改为：
  - `QMatrix4x4 proj; proj.perspective(...) / proj.ortho(...)`
  - `QMatrix4x4 view; view.translate/rotate(...)`
  - 组合成 `MVP`（或拆分 `Model/View/Proj`）写入 UBO
- `gluPerspective`、`gluOrtho2D` 完全移除

#### 4.1.4 光照与颜色
目前通过固定管线 `GL_LIGHTING` 实现基础光照。
RHI 下需要自定义 shader：
- **最小可行**：Lambert 漫反射 + 方向光/点光（对应原 `LIGHT0`）
- 透明支持：支撑透明度、Fence alpha（现 `fenceAlpha/supportAlpha`）

#### 4.1.5 Display List 替换（核心工作量）
当前模型与支撑大量依赖 display list：
- `ModelData::normDispLists/flippedDispLists`
- `B9SupportAttachmentData::dispListIndx`
- `B9ModelInstance::triPickDispLists`

迁移策略（推荐）：
- 引入 `MeshGpuResources`（示例命名）
  - `QRhiBuffer *vbuf`, `*ibuf`（或仅 vbuf，无索引）
  - 顶点格式：position/normal（未来可加 color/uv）
- `ModelData` 加缓存：
  - CPU side 仍保留 `triList`（用于几何计算、支撑、切片等）
  - GPU side：由 `triList` 生成一次静态 buffer
- flipped 模型：
  - 方案 A：GPU 侧用负缩放（model matrix `scale(-1,1,1)`）+ 调整法线
  - 方案 B：生成第二套 flipped 顶点数据（与现逻辑更一致，但更占内存）
  - 推荐先用 **方案 A**，减少内存与实现复杂度

> 注意：当前代码有“大模型 OOM 时稀疏三角绘制”的逻辑（`displaySkipping += 10`）。RHI 下同样需要：
- CPU 侧根据 `displaySkipping` 生成较稀疏的顶点数组
- 或者在 shader/绘制时用 `firstVertex/vertexCount` 做分段绘制（更复杂）

### 4.2 picking（实例/支撑/三角形）迁移

#### 4.2.1 现状
- 通过 `glColor3ub` 输出唯一颜色 ID（实例 pickcolor、支撑 pickcolor、三角 pick color 序列）
- 读取鼠标位置像素 → 反解得到对象

#### 4.2.2 RHI 等价实现（推荐保持思路一致）
- 增加一个 **离屏 picking pass**：
  - 目标纹理：`QRhiTexture`（RGBA8）
  - 深度：`QRhiRenderBuffer`（Depth24/Depth32）
  - render pass：只输出纯色（不做光照/透明混合），每个可选对象输出其 ID
- 鼠标点击/移动时：
  - 触发一次 picking pass 渲染
  - 用 `QRhiReadbackResult` 将鼠标点像素读回 CPU

#### 4.2.3 三角形 picking
当前 `FormTriPickDispLists()` 会对每个三角形输出不同颜色（r/g/b 递增），并且可能拆成多个 list。
RHI 下建议：
- 不再为 pick 单独建“超大 pick mesh”（否则内存与上传成本太高）
- 优先做 **GPU picking 降级策略**：
  - 先对实例/支撑做 pick
  - 三角 pick 仅在需要（支撑吸附等）时渲染当前实例的 pick pass
  - 仅上传“当前实例”的 pick 顶点颜色数据（动态）或通过 instanceID+triangleID 编码

### 4.3 SliceContext（离屏切片渲染）迁移

#### 4.3.1 现状
`SliceContext : QGLWidget` 使用 OpenGL 2D 正交投影，调用 `Slice::Render()`（内部 `glBegin(GL_TRIANGLES)`）绘制。

#### 4.3.2 目标（RHI Offscreen Renderer）
建议不再使用 `QRhiWidget` 做离屏，而是创建一个独立的 **Offscreen RHI Renderer**：
- 输入：`Slice` 的 loop/segment 数据（CPU）
- 输出：`QImage`/raw bytes（用于导出/预览/投影）
- 实现：
  - 创建 `QRhi`（可复用主界面 rhi，也可独立；优先复用，避免多后端上下文）
  - 建立 `QRhiTextureRenderTarget`（分辨率为 projector resolution）
  - 绘制 2D 三角形填充/轮廓线
  - `readback` 结果转 `QImage`

#### 4.3.3 立即模式替换
`Slice/Loop` 中的 `glBegin` 需要替换为：
- 把三角 strip（`triangleStrip`）转换为顶点数组（position2D/position3D(z=0)）
- 一次性上传到 `QRhiBuffer`
- pipeline：
  - 顶点着色器：把 2D 坐标乘以 ortho 矩阵
  - 片元着色器：输出指定颜色（填充红/绿等，按现逻辑）

## 5. 分阶段迁移路线（推荐）

> 说明：由于现渲染大量依赖 OpenGL 固定管线与 display list，**不可能“一步到位”直接替换成 QRhiWidget 而不影响功能**。因此建议分阶段，每阶段都能编译运行，并且功能逐步对齐。

### 阶段 0：准备与基线（1-3 天）
- 目标：Qt6 能编译，渲染保持旧 OpenGL（临时），建立自动化验证入口
- 任务：
  - 将工程切换到 Qt6，并以 **CMake 作为主构建系统**（先让 CMake 版本可编译运行）
  - 替换 `QGLWidget` → `QOpenGLWidget`（临时过渡，仅用于快速把 Qt6 跑起来）
  - 移除 `QtOpenGL` 旧 include（用 `QOpenGLFunctions`/`QOpenGLExtraFunctions` 适配）
  - GLU 替换：`gluPerspective/gluOrtho2D` → `QMatrix4x4` + 自己实现投影（仍可在 OpenGL 里用 shader 或固定管线替代；但 Qt6 core profile 下固定管线可能不可用）

> 备注：此阶段是“工程能跑”的保险。你最终目标是 QRhiWidget，但建议先让 Qt6 版本能启动并进入主界面。

### 阶段 1：引入渲染抽象层（3-7 天）
- 目标：渲染调用点与业务解耦，为 RHI 后端铺路
- 任务：
  - 抽象出：
    - `SceneState`（相机、视图模式、透明度参数、XRay 参数等）
    - `Renderable`（模型实例、支撑、build area、overlay）
  - `WorldView` 中：
    - 保留事件与工具逻辑
    - 将 `DrawInstances/DrawBuildArea/...` 的数据准备与绘制拆分

### 阶段 2：3D 视图切换为 `QRhiWidget`（核心阶段，2-4 周）
- 目标：`WorldView` 完整替换为 `WorldViewRhiWidget`，主界面 3D 功能对齐
- 任务拆分：
  - **2.1 渲染框架搭建**
    - `QRhiWidget` 初始化、resize、渲染循环
    - 深度测试、混合、MSAA（如果需要）
  - **2.2 基础几何绘制**
    - Build area / 坐标系 / fence（先用简单线框 pipeline）
  - **2.3 模型渲染**
    - `ModelData` 从 triList 生成静态 VBO/IBO
    - 支持：翻转/缩放/旋转/平移
    - 支持：光照（最小 lambert）
    - 支持：大模型稀疏绘制策略
  - **2.4 支撑渲染**
    - 将 `B9SupportAttachmentData` 的 display list 变成 mesh buffer
    - 支撑透明度与选中高亮
  - **2.5 X-Ray 与透明逻辑**
    - 近裁剪调整逻辑迁移到 shader/投影矩阵
    - 支撑/模型分 pass 绘制，保证深度与混合正确
  - **2.6 picking**
    - 实例/支撑 picking pass
    - 三角 picking 先实现“单实例 pick”版本

### 阶段 3：SliceContext 离屏切片渲染迁移到 RHI（1-2 周）
- 目标：完全移除 `SliceContext : QGLWidget`，改为 RHI offscreen
- 任务：
  - 设计 `SliceRhiRenderer`（独立类）
  - 将 `Slice/Loop` 的立即模式渲染改为：生成 vertex buffer + pipeline
  - 输出 `QImage` 并替代原使用点（导出/预览/投影）

### 阶段 4：清理 OpenGL 依赖与工程收敛（3-7 天）
- 目标：工程不再依赖 `QT += opengl`（除非你仍希望保留 OpenGL 后端），删除 GLU/GLUT 链接
- 任务：
  - 删除 `QtOpenGL` include 与 `LIBS += -lglut -lglu` 等
  - 删除或隔离 `OS_GL_Wrapper.h` 中与旧 GL 相关的内容（如仅用于 GL error 映射则重写为通用）
  - 文档化后端选择与已知驱动问题

## 6. 文件/类迁移清单（建议映射）

### 6.1 需要重点改造的文件
- `b9layout/worldview.h/.cpp`
  - `QGLWidget` → `QRhiWidget`
  - `initializeGL/paintGL/resizeGL` → RHI 生命周期函数
  - `ResetCamera`：从 OpenGL 矩阵栈改为 `QMatrix4x4`
- `b9layout/slicecontext.h/.cpp`
  - 最终移除或改为纯逻辑类（不再继承 Widget）
- `b9layout/slice.cpp`、`b9layout/loop.cpp`
  - 移除 `glBegin/glVertex/...`，改为生成三角形/线段顶点数组
- `b9layout/modeldata.cpp`
  - `FormNormalDisplayLists/FormFlippedDisplayLists` → `BuildGpuMeshBuffers`
- `b9layout/b9modelinstance.cpp`
  - `RenderGL/RenderPickGL/RenderTrianglePickGL` → 提供渲染所需的变换与资源引用
- `b9supportstructure.cpp`
  - `B9SupportAttachmentData::FormDisplayList` → GPU mesh

### 6.2 UI 调用点（替换 Widget 类型）
- `b9layout/b9layout.cpp`
  - `pWorldView = new WorldView(NULL,this);` → `new WorldViewRhiWidget(...);`
  - `ui.WorldViewContext->addWidget(pWorldView);` 保持不变

## 7. 风险与应对

### 7.1 最大风险：固定管线/Display List → RHI 的工作量
- **风险**：渲染代码需要从“状态机式 OpenGL”完全改写为“pipeline + shader + buffer”。
- **应对**：分阶段 + 先抽象 + picking/离屏先做最小可行。

### 7.2 picking 读回性能
- **风险**：每次鼠标移动都 readback 会卡顿。
- **应对**：
  - 鼠标移动仅在需要（hover tooltip/吸附）时触发
  - 仅在点击时做高精度 pick
  - 支撑编辑模式下才启用高频 pick

### 7.3 Qt6 版本差异
- **风险**：`QRhiWidget` 与 RHI API 在 Qt6 不同小版本能力差异。
- **应对**：计划中锁定 Qt 版本为 **6.9**，并在 CI/开发机统一。

### 7.4 跨平台后端差异
- **风险**：不同后端（D3D/Vulkan/Metal）对 shader 语法、纹理格式、深度范围有差异。
- **应对**：
  - 使用 Qt 的 shader 工具链（`.qsb`），统一从 HLSL/GLSL 编译
  - 避免依赖未定义行为（例如深度范围、clip space 差异）

## 8. 验证与回归清单

### 8.1 视觉回归（3D）
- 视角切换（Top/Front/Right/Left/Bottom/Back）一致
- 透视/正交切换一致
- X-Ray 模式显示一致（裁剪效果、支持透明度）
- Fence 越界提示一致
- 支撑显示/隐藏一致

### 8.2 交互回归
- 模型选择（单选/多选）、拖动、旋转、缩放
- 支撑添加/删除/修改（picking 准确）

### 8.3 切片/导出回归
- 同一工程（同参数）导出切片图像像素级一致或可接受误差范围一致
- 轮廓/填充颜色规则一致

### 8.4 性能
- 大模型加载后帧率不显著低于旧版本
- picking 在常用操作下无明显卡顿

## 附录 A：建议的实现细节（关键点提示）

### A.1 shader 管线与 Qt shader 工具链
RHI 通常使用 Qt 的预编译 shader（`.qsb`）。建议：
- 为 3D 模型准备：
  - `model.vert`：输入 position/normal，输出 world normal
  - `model.frag`：lambert + 颜色/选中高亮
- 为 picking 准备：
  - `pick.vert/pick.frag`：输出纯色 ID
- 为 2D slice 准备：
  - `slice.vert/slice.frag`

### A.2 深度与透明
支撑透明 + XRay 很容易出现排序/深度问题。建议：
- 不透明对象先画（depth write on）
- 透明对象后画（depth test on, depth write off）
- 必要时对支撑做简单排序（按相机距离）

### A.3 与现业务代码的最小侵入
- `B9Layout`、工具逻辑、数据结构尽量不动
- 把“渲染所需的数据提取”作为接口加在数据类上，而不是在 widget 里到处访问内部字段

### A.4 在 CMake 中编译并打包 `.qsb`（强制要求项）

#### A.4.1 为什么必须在构建期编译
Qt6 RHI 推荐使用 `.qsb`（Qt Shader Baker 输出），以保证：
- 跨后端（D3D/Vulkan/Metal/OpenGL）一致性
- 启动时不依赖运行时编译器（减少驱动差异与部署问题）

#### A.4.2 CMake 集成方式（推荐：`qt_add_shaders`）
在 Qt 6.x 的 CMake API 中，通常使用 `qt_add_shaders()`（本计划目标 Qt 版本为 6.9）：

```cmake
find_package(Qt6 6.9 REQUIRED COMPONENTS ShaderTools)

qt_add_shaders(B9Creator "b9creator_shaders"
  PREFIX "/shaders"
  FILES
    shaders/model.vert
    shaders/model.frag
    shaders/pick.vert
    shaders/pick.frag
    shaders/slice.vert
    shaders/slice.frag
)
```

要点：
- `Qt6::ShaderTools` 提供 `qsb` 工具链，确保构建机能编译 shader
- `PREFIX "/shaders"` 表示最终资源路径（运行时可用 `:/shaders/...` 访问）
- `qt_add_shaders` 会在构建时生成 `.qsb` 并自动加入目标（随构建系统增量更新）

#### A.4.3 shader 源格式建议
为降低多后端差异，建议：
- 最终以 Qt 官方推荐的 shader 语言/布局规范编写（配合 qsb）
- 明确顶点输入 layout（position/normal/color 等）
- 统一使用 UBO（相机矩阵、材质参数、颜色等）

#### A.4.4 增量构建与调试建议
- shader 文件修改后应触发 `.qsb` 重生成（`qt_add_shaders` 通常可自动处理）
- 发生渲染异常时：
  - 先确认运行时加载的是 `:/shaders/*.qsb` 而不是源文件
  - 对比不同后端（例如 Windows D3D11 vs OpenGL）行为差异

#### A.4.5 替代方案：当 `qt_add_shaders` 不可用时用 `qsb` 自定义编译
在某些环境中（例如 Qt 版本过低、Qt 的 CMake API 不完整、或你希望更明确地控制输出路径），可以用 `add_custom_command()` 直接调用 `qsb`：

```cmake
find_package(Qt6 6.9 REQUIRED COMPONENTS ShaderTools)

get_target_property(_qsb_exe Qt6::qsb LOCATION)

set(SHADER_SOURCES
  ${CMAKE_CURRENT_SOURCE_DIR}/shaders/model.vert
  ${CMAKE_CURRENT_SOURCE_DIR}/shaders/model.frag
)

set(SHADER_QSB_OUTPUTS
  ${CMAKE_CURRENT_BINARY_DIR}/shaders/model.vert.qsb
  ${CMAKE_CURRENT_BINARY_DIR}/shaders/model.frag.qsb
)

add_custom_command(
  OUTPUT ${SHADER_QSB_OUTPUTS}
  COMMAND ${CMAKE_COMMAND} -E make_directory ${CMAKE_CURRENT_BINARY_DIR}/shaders
  COMMAND ${_qsb_exe} --glsl "100es,120,150" --hlsl 50 --msl 12
          -o ${CMAKE_CURRENT_BINARY_DIR}/shaders/model.vert.qsb
          ${CMAKE_CURRENT_SOURCE_DIR}/shaders/model.vert
  COMMAND ${_qsb_exe} --glsl "100es,120,150" --hlsl 50 --msl 12
          -o ${CMAKE_CURRENT_BINARY_DIR}/shaders/model.frag.qsb
          ${CMAKE_CURRENT_SOURCE_DIR}/shaders/model.frag
  DEPENDS ${SHADER_SOURCES}
  VERBATIM
)

add_custom_target(b9creator_shaders ALL DEPENDS ${SHADER_QSB_OUTPUTS})
add_dependencies(B9Creator b9creator_shaders)

qt_add_resources(B9Creator "b9creator_shaders_qrc"
  PREFIX "/shaders"
  FILES
    ${CMAKE_CURRENT_BINARY_DIR}/shaders/model.vert.qsb
    ${CMAKE_CURRENT_BINARY_DIR}/shaders/model.frag.qsb
)
```

说明：
- 上例中 `--glsl/--hlsl/--msl` 参数需按你的 Qt 版本与目标后端实际调整。
- 该方案会把 `.qsb` 输出到构建目录，再通过 `qt_add_resources` 打包进可执行文件。
- 这种方式控制力更强，但维护成本也更高，因此优先推荐 `qt_add_shaders`。
